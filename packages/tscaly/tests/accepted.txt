# accepted.txt — deviations from the reference that are known and argued.
# Our counterpart to the reference's testdata/submoduleAccepted.txt.
#
# FORMAT, one deviation per line, tab-separated:
#
#     <case>\t<artifact>\t<reason>
#
# <case> is the runner's case key: the path under testdata/tests/cases/ (or
# under packages/tscaly/tests/ for our own fixtures) with the extension dropped
# and every `/` replaced by `_`. It is path-derived rather than a basename
# because conformance/ nests and two directories there can hold the same file
# name — a basename key would let one case's entry silently excuse another's.
#
# <reason> must begin with one of three classifiers:
#
#   DIVERGENCE:  a deliberate difference from the reference. Permanent. These
#                are the interesting entries and each one needs its argument
#                written out, not a pointer to one. Example to come: node IDs
#                are assigned deterministically at parse time here, where the
#                reference assigns them lazily by CAS into the shared AST.
#   UNPORTED:    the construct is not ported yet. Temporary; the count is a
#                progress bar. NOTE that a construct the scanner RECOGNIZES as
#                unported does not belong here — it reports itself at runtime and
#                the runner counts it separately. This classifier is for a
#                deviation that shows up as a differing token stream.
#   UPSTREAM:    the reference's own output is wrong or host-dependent. Rare,
#                and each one needs evidence, not an opinion.
#
# THE LIST IS MAINTAINED BY HAND. There is deliberately no --update mode: a
# switch that rewrites this file turns the discipline into a rubber stamp. Add
# entries one at a time, with the reason typed by a person.
#
# The runner also reports entries that now MATCH, and fails on them. A stale
# exception is a lie in the other direction, and without that check the list
# rots into a record of things that used to be true.
#
# <artifact> is `tokens`, `ast`, `jsdoc`, `symbols` or `types` — which yardstick
# the entry excuses. It is a column of its own because a case routinely deviates
# on one and matches on the other while a slice is in flight, and one key for both
# would let an entry written for the parser silently excuse the scanner.
#
# ★★★ FOR THE `types` YARDSTICK AN ENTRY ALSO EXCUSES AN ORACLE THAT CANNOT ANSWER
# (slice 46). tests/oracle/types.go exits 3 when the reference PANICS on a unit,
# and compare.py accepts that only against an entry here — otherwise it is a
# failure. The reason: a column that cannot fail the run is a column that is not
# measured (slice 26's c4 found exactly that defect in the four-yardstick sums), so
# an oracle that died on every unit must not read as a green "no reference answer".
#
# ── entries ──────────────────────────────────────────────────────────────────
#
# ★★★ THE FIRST ENTRY IN THE FILE'S HISTORY, and it is slice 46's: forty-five
# slices produced none, because every difference either matched the reference or
# reported itself as unported. This one is not a difference — it is the REFERENCE
# refusing to answer, which is why it is UPSTREAM and why it needed a mechanism of
# its own (the oracle's exit 3).
fixtures_parser_jsdoc_reparse_full_signature_guard	types	UPSTREAM: the reference PANICS. `interface I { /** @type {string} */ m() }` in a .js file nil-dereferences inside the checker: checkFunctionOrMethodDeclaration asks getTypeFromTypeNode for the method's JSDoc-reparsed type, whose Parent is nil, and getAliasSymbolForTypeNode reads it (checker.go:23629). Evidence rather than opinion: a walk of the whole tree finds NO nil parent, because the node sits in the `full_signature` slot ForEachChild does not visit (§3.5ao) — so it is parse-time state and not this oracle's stub program. Bounded by measurement: a function declaration's @type, a `declare class` method and the same source as .ts are all fine, and this is the ONLY unit of 17 807 that does it.

# ★★★ SLICE 92'S TWO, AND THE INSTRUMENT IS WHAT MAKES THEM VISIBLE. Both are the
# SAME divergence, and it has been written down at its own line in parser.scaly
# since slice 50 — `add_deep_clone_reparse` is a SHALLOW copy (`set c: *n`), so a
# JSDoc overload signature cloned for a second and third `@overload` tag SHARES
# every descendant with the first. Nothing could see it: the AST dump prints a
# node's kind, pos and end, which a shared child and a cloned one answer
# identically, and the symbols dump prints symbols, which they also share. The
# FLOW dump is the first artifact that reads a per-node SLOT written three times
# — the shared node keeps the LAST bind's flow node and the reference's three
# clones keep three — so the divergence became measurable on the day the fifth
# yardstick landed and not before.
#
# ★ It is filed as DIVERGENCE rather than fixed here because a true deep clone
# has to rebuild the NodeData payload arm by arm (134 of them) and re-parent every
# descendant; that is a parser slice with its own controls, not a line in a binder
# slice. It is bounded: 2 units of 1 453, both `@overload`-heavy JSDoc, and both
# agree on every other yardstick.
compiler_jsDocGenericOverloads	flow	DIVERGENCE: `add_deep_clone_reparse` is a shallow copy, so the second and third JSDoc `@overload` signature share their descendants with the first instead of cloning them. One shared node is bound once per occurrence and keeps the LAST flow node; the reference's three clones keep three. Visible only here — kind/pos/end and the symbol are identical for a shared child and a cloned one, which is why four yardsticks and 42 slices could not see it.

# ★★★ FOUR UNITS, ONE CAUSE, AND THE CAUSE IS §3.11 RATHER THAN THIS SLICE. Until
# the chain landed, every one of these stopped at `type-of-node` before its dump
# was compared at all, so a diagnostic the reference makes and this port does not
# was invisible in both directions. The cause is the one the globals table's own
# note states: `initializeChecker` merges the top-level locals of every non-module
# file of the PROGRAM, and the oracle's program is lib.es5.d.ts plus the unit while
# this Checker has the unit alone. So `Object`, `Uppercase` and `Promise` are names
# the reference's table holds and ours does not — and each of the four missing
# diagnostics is exactly a COLLISION with one of them.
#
# ★★ IT IS THE MISSING-REPORT DIRECTION, NEVER A WRONG ONE, which is what makes
# these acceptable rather than defects: our table is a strict SUBSET of upstream's
# and never holds a different name, so a name we miss is a report we do not make.
# tests/diagcheck.sh asserts exactly that relation (our C lines a SUBSEQUENCE of
# the reference's) and stays green on all four; run.sh's types comparison is exact
# and therefore does not.
#
# ★ Each entry names the collided LIB declaration, because the entry has to be
# falsifiable: load the lib and the diagnostic appears, and these lines then fail
# as stale — which is the check that keeps this list from rotting.
fixtures_checker_class_name_object	types	UNPORTED: the LIB (§3.11). `class Object {}` collides with lib.es5's `interface Object`, so the reference adds TS2300 ("Duplicate identifier 'Object'") beside the TS2725 both sides agree on. Our globals table holds the unit's own top-level names only, so there is no second declaration to collide with. Missing-report direction; diagcheck's subsequence relation is green.
fixtures_checker_type_alias_intrinsic	types	UNPORTED: the LIB (§3.11). `type Uppercase<S extends string> = intrinsic` collides with lib.es5's own `type Uppercase<S extends string>`, so the reference adds TS2300 at the 9-character name. The four TS2795 lines both sides agree on. Missing-report direction.
fixtures_checker_type_alias_reserved_name	types	UNPORTED: the LIB (§3.11). `type Object = number` collides with lib.es5's `interface Object` and the reference adds TS2300 at the 6-character name; `string` and `undefined` are RESERVED rather than duplicated and their two TS2457 lines both sides agree on, which is what isolates the cause to the table.
fixtures_checker_collision_promise	types	UNPORTED: the LIB (§3.11). `class Promise {}` MERGES with lib.es5's `interface Promise<T>`, and the merge is what produces both halves of this diff: TS2428 ("All declarations of 'Promise' must have identical type parameters") and the declared type's name, `Promise<T>` upstream against `Promise` here. Without the lib there is one declaration, it has no type parameters, and neither half can arise. Missing-report direction for the C line; for the T lines it is the same single cause and not a naming defect — type_to_string prints the type parameters it is given (fixtures_checker_declared_type_class_generic pins that).
