# slow.txt — units that TERMINATE but not inside this gate's time budget.
#
# ★★★ WHY THIS FILE EXISTS, AND WHY IT IS NOT accepted.txt. A TIMEOUT is the one
# outcome the runner could not describe: `compare.py` returns it BEFORE it reads
# accepted.txt, and rightly so — an accepted DEVIATION is a statement about an
# ANSWER, and a unit that never answers has none to argue about. But there is a
# third thing between "answers differently" and "does not terminate", and slice
# 171 measured one: `excessivelyDeepConditionalTypes` answers UNPORTED after
# 223 s per artifact — the same verdict it carried before that slice, at six
# artifacts x 224 s = about 22 minutes of wall clock for an answer we already
# have. Raising TSCALY_TIMEOUT buys that verdict at a price no gate can pay;
# calling it UNEXPLAINED says the port does something unknown there, which is
# false. This file says the true thing.
#
# FORMAT, one unit per line, tab-separated:
#
#     <case>\t<seconds>\t<reason>
#
# <case> is the runner's case key, exactly as accepted.txt uses it. The entry is
# per UNIT and not per artifact, because a timeout is a property of the PROCESS:
# all six dumps of a unit hit it together.
#
# <seconds> is the MEASURED wall clock of one artifact, so that the entry states
# a number a later reader can re-measure rather than an impression. Update it
# when it moves.
#
# <reason> must name the CAUSE, not the symptom. "it is slow" is not a reason.
#
# ★★★ IT CANNOT ROT SILENTLY, WHICH IS THE WHOLE DIFFERENCE BETWEEN THIS AND A
# SUPPRESSION LIST. The runner reports every entry it did NOT need — a listed
# unit that finished — and FAILS on it, exactly as it does for an accepted.txt
# entry that now matches. So the file shrinks by itself the moment the cause is
# fixed, and an entry nobody can justify is one run away from being noticed.
#
# ★★★ THE ANTI-ROT CHECK IS THE RUNNER'S ALONE, AND `walkcheck` PROVED WHY THE
# HOUR THIS FILE LANDED. An entry states a cost under ONE budget, and the
# instruments do not share one: run.sh allows TSCALY_TIMEOUT (none by default since
# 2026-09-27, 60 s before) for a full CHECK per artifact,
# checkloop.py allows 10 s, and a WALK is not the same work as a check — the one
# entry this file has held WALKED inside 10 s and did not CHECK inside 223 s. The
# other instruments
# may therefore USE an entry to excuse a timeout, but only compare.py, which owns
# the gate the entry was written for, may call one stale. The first version
# reported it everywhere and turned a correct list into a red walkcheck.
#
# ★ A listed unit is NOT a pass. It is counted in its own column, printed by
# name on every run, and it is not in `matched`. The rule this suite keeps
# writing applies here too: a column that cannot be read is a column that is not
# measured.
#
# THE LIST IS MAINTAINED BY HAND. There is no --update mode, for accepted.txt's
# reason. ★★★AND AN ENTRY NEEDS A MEASUREMENT BEFORE IT NEEDS A LINE: the seconds
# column is not decoration, it is the evidence that somebody let the unit finish
# and looked at the verdict. An unmeasured entry would be exactly the rubber
# stamp this format exists to prevent.
#
# ★★★ THE LIST IS EMPTY, AND IT EMPTIED ITSELF. Its one entry —
# `excessivelyDeepConditionalTypes`, 223 s per artifact, cause: the relation had
# no result cache — was written on 2026-09-10 and removed the same day by the
# anti-rot check above, on the first run after slice 172 gave the relation its
# cache and took that unit from 224 s to 2.5 s. The file stays because the
# outcome it names is real and will recur; that it names nothing today is the
# mechanism working, not the mechanism going unused.
